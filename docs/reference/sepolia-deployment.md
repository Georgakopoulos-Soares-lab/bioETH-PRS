# Sepolia Deployment Guide

This document describes the pre-flight checklist, step-by-step deployment
procedure, and post-deployment validation for bioETH PRS on Sepolia testnet.

---

## Why Sepolia, not local Docker

Zama deprecated the local Docker fhEVM node.  The only way to run real TFHE
ciphertext operations is on the **Sepolia testnet** via Zama's hosted
coprocessor and KMS.  Local Hardhat tests use a mock coprocessor that performs
plaintext arithmetic — correct for logic validation but not for measuring real
gas costs, HCU budgets, or cryptographic correctness.

---

## Pre-flight checklist

Before deploying, verify every item in this list:

### 1. Compile cleanly

```sh
npm run build
```

All four contracts must compile without errors.

### 2. Local tests pass

```sh
npm test
```

All 64 tests must pass.  Do not deploy with failing tests.

### 3. Obtain Sepolia ETH

* Faucets: [sepoliafaucet.com](https://sepoliafaucet.com), [Alchemy Sepolia faucet](https://sepoliafaucet.com), or the [Infura faucet](https://www.infura.io/faucet/sepolia).
* Estimated cost per full deployment + 100-SNP validation run: **~0.05–0.15 ETH** (varies by current Sepolia gas price).
* The HCU probe deploys 5 independent contract sets — add ~0.05 ETH for that.

### 4. Set Hardhat credential variables

Credentials are stored by Hardhat's built-in variable system — never in
`.env` files or committed to the repo.

```sh
# Your wallet mnemonic (12 or 24 words)
npx hardhat vars set MNEMONIC

# Infura project ID for Sepolia RPC (free tier is fine)
# Alternative: set INFURA_API_KEY="" and rely on the public Ankr fallback RPC
npx hardhat vars set INFURA_API_KEY
```

Verify the vars are set:

```sh
npx hardhat vars list
```

Expected output includes `MNEMONIC` and `INFURA_API_KEY`.

### 5. Check deployer balance

```sh
npx hardhat run --network sepolia - <<'EOF'
const [d] = await ethers.getSigners();
console.log(d.address, ethers.formatEther(await ethers.provider.getBalance(d.address)), "ETH");
EOF
```

## Deployment

### Step 1 — Deploy contracts

```sh
npm run deploy:sepolia
```

This runs `scripts/deploy.ts` and deploys in order:

1. `GenomicRegistry` — no constructor args
2. `ModelMarketplace` — inherits `ZamaEthereumConfig`, auto-configures for Sepolia
3. `PRSComputeEngine(marketplaceAddress, registryAddress)`
4. `ResultOracle` — inherits `ZamaEthereumConfig`

`ZamaEthereumConfig` detects `chainId = 11155111` at runtime and wires the
Zama coprocessor, KMS verifier, input verifier, and gateway automatically.
No manual gateway addresses are needed.

Output is saved to `deployments/sepolia.json`.  This file is gitignored;
record the addresses in your lab notebook or paper appendix.

### Step 2 — Run the 100-SNP validation

```sh
npm run validate:sepolia
```

This runs `scripts/sepolia_validation.ts` against the deployed contracts.  It:

* Publishes a 100-SNP public GWAS model from the HEPRS fixture.
* Creates a PRS job (registry ACL check fires here).
* Uploads 10 SNP chunks of 10 values each — real TFHE ciphertexts generated by
  the Zama relayer and verified by the on-chain InputVerifier.
* Runs 10 `computeChunk` calls.
* Calls `finalize()` and captures the `JobFinalized` event.
* Decrypts the score via `fhevm.userDecryptEuint` (EIP-712 signing → relayer →
  KMS re-encryption flow).
* Asserts the decrypted score matches the expected plaintext value.

Results are written to `deployments/sepolia-validation-100snp.json`.

Expected runtime on Sepolia: **15–90 minutes** depending on network congestion
and Zama coprocessor queue depth.

### Step 3 — Probe the HCU ceiling

```sh
npm run probe:hcu
```

This runs `scripts/probe_hcu_ceiling.ts` and tests `computeChunk` with chunk
sizes `[10, 15, 20, 25, 32]`.  The result determines the real Sepolia HCU
budget and the maximum safe `chunkSize` for future model publications.

Results are written to `deployments/sepolia-hcu-probe.json`.

After this step, fill in the "Sepolia results" table in
`docs/architecture-roadmap.md §7-I`.

## Decryption: mock vs Sepolia

| Environment | Decryption call | What happens |
| --- | --- | --- |
| Local Hardhat (`--network hardhat`) | `fhevm.debugger.decryptEuint(...)` | Reads plaintext from mock coprocessor state — instant, no KMS |
| Sepolia (`--network sepolia`) | `fhevm.userDecryptEuint(type, handle, contract, signer)` | EIP-712 signed request → Zama relayer → KMS re-encryption → returned plaintext |

The validation script uses `fhevm.isMock` to choose the correct path
automatically.  Both paths are implemented; no code changes are needed to
switch networks.

## Troubleshooting

**`HCUTransactionLimitExceeded` on computeChunk**
The chunk size is too large for the current HCU budget.  Lower `chunkSize`
when publishing the model.  On mock, the ceiling is 10; on Sepolia it may be
higher — run `npm run probe:hcu` to measure.

**`InsufficientFunds` or OOG on deployment**
Top up the deployer wallet via the Sepolia faucet.

**`userDecryptEuint` throws or times out**
The Zama relayer may be congested.  Wait a few minutes and retry.  Also verify
that `FHE.allow(handle, signer.address)` was called in `finalize()` — without
it the KMS will reject the re-encryption request.

**Deployed addresses look wrong in `deployments/sepolia.json`**
Re-run `npm run deploy:sepolia`.  The script overwrites the file.

**Validation script deploys fresh contracts instead of reusing sepolia.json**
The script reuses `deployments/sepolia.json` only on `--network sepolia`.  On
local mock it always deploys fresh (intentional — no persistent state).
